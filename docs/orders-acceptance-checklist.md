# Приёмка раздела «Orders» — чеклист владельца

Дата подготовки: 2026-08-03. Проверяется всё, что выложено на прод:
миграции кассы `139–141` и редизайн раздела (фазы 1–7).

**Что уже проверено и переспрашивать не нужно:** правила (361 юнит-тест),
сервер (`supabase test db` — 1072 проверки), поведение панели, пагинации,
клавиатуры и адаптива — браузерными прогонами на синтетических данных.

**Что может проверить только владелец:** совпадает ли увиденное с реальной
работой заведения — настоящие заказы, настоящая касса, настоящий телефон.
Ниже только это.

Обозначения: **⛔ стоп** — если не сошлось, дальше не идём и пишем
разработчику; **⚠️ ожидаемо** — так и задумано, это не дефект.

---

## 0. Подготовка (5 минут)

| Что | Где |
|---|---|
| Кабинет | `https://www.angle.co.il/account` → **Work → Orders** (адрес без `www` отдаёт 403 — это давняя настройка домена, не поломка) |
| Гостевая страница | `https://menu.angle.co.il/order/<слаг точки>` |
| Касса | терминал, экран «Онлайн» |

Заведите **одну тестовую заявку** с гостевой страницы на небольшую сумму.
Если точка обслуживается кассой — помните, что принятая заявка станет
настоящим заказом: не оставляйте его открытым.

## 1. Касса не сломалась (делать первым)

Миграции уже на проде, фронт кассы выложен с требованием версии `141`.

- [ ] Терминал открывается, экран продажи работает.
- [ ] **⛔ Нет экрана «Требуется обновление базы данных»** и нет плашки
      «обновите приложение», которая не уходит после перезагрузки.
- [ ] Экран «Онлайн» открывается, новая заявка на нём видна, «Принять»
      работает как раньше.
- [ ] Смена открывается и закрывается, чек печатается.

Если что-то из этого не так — остановитесь: остальное подождёт.

## 2. Брони не сломались

Затрагивалась общая боковая панель (у неё появился режим без затемнения,
брони остались на прежнем).

- [ ] Reservations → полотно → открыть визит: панель открывается, **фон
      затемнён**, клик по затемнению закрывает её, Escape закрывает.
- [ ] Отмена визита с причиной работает.
- [ ] Список броней, лист ожидания и план зала открываются без ошибок.

## 3. Заказы: первый взгляд

- [ ] Раздел открывается **таблицей**, а не карточками.
- [ ] На экране ноутбука видно **не меньше десяти** заказов сразу.
- [ ] У каждой строки: номер, время, гость, способ выдачи, канал,
      состояние, штуки, сумма.
- [ ] Сумма показана с копейками и знаком вашей валюты.
- [ ] **⛔ Заказы прошлых дней не лежат вперемешку с сегодняшними.**
- [ ] Вкладка «Scheduled» видна, только если у вас есть заказы «ко времени»
      на будущие дни. ⚠️ Если предзаказов нет — вкладки нет, так и задумано.

## 4. Номер заявки

- [ ] У новой тестовой заявки в кабинете есть номер вида `#1042`.
- [ ] Следующая заявка получает следующий номер.
- [ ] Номер **не сбрасывается** на следующий день (проверить завтра).
- [ ] У второй точки (если их несколько) своя нумерация — это нормально.
- [ ] ⚠️ Гость и кассир номер пока **не видят**: поле уже приходит в
      ответе сервера, но экраны его не показывают. Отдельная задача.

## 5. Панель заказа

Открыть заказ щелчком по номеру.

- [ ] Панель справа, таблица под ней **осталась видна**.
- [ ] Заголовок — `Order #…`, а не имя гостя.
- [ ] Видны: состояние, источник, способ выдачи, время, гость, телефон,
      позиции с модификаторами, заметка, итог.
- [ ] Позиции и сумма совпадают с тем, что заказал гость.
- [ ] **История**: «Received · Guest» с временем, дальше решения с именем
      того, кто их принял.
- [ ] ⚠️ У заказов, созданных **до 3 августа**, в истории только «получен»
      и последнее решение — промежуточные шаги не записывались, и
      придумывать их нельзя.
- [ ] Escape закрывает панель; щелчок по соседнему заказу открывает его,
      **не закрывая** панель.

## 6. Точка на кассе: честный read-only

Только если точка обслуживается кассой.

- [ ] **⛔ В кабинете нет кнопок «Принять» / «Отклонить»** — цикл живёт на
      кассе.
- [ ] В панели заказа есть блок «Handled on the register».
- [ ] При **открытой** смене: «спросите заказ #… на кассе».
- [ ] Закройте смену на кассе, обновите кабинет: текст меняется на
      «смены нет, поэтому на кассе этот заказ пока никто не видит».
      **⛔ Это ключевая проверка честности раздела.**
- [ ] У принятой на кассе заявки в панели виден её номер на терминале
      (`#43`) и его состояние.
- [ ] **⛔ Нигде нет кнопки «Открыть на кассе»** — такой ссылки не
      существует, и обещать её нельзя.

## 7. Точка без кассы: полный цикл

Только если точка работает без терминала (standalone).

- [ ] «Accept» переводит заявку в принятые, строка меняет состояние.
- [ ] Появляется подтверждение вида «#1042 is now Accepted».
- [ ] Доступны «Start preparing», «Ready», **«Complete»** — последний
      теперь есть и из «Accepted», без прогона через «Ready».
- [ ] «Reject» и «Cancel» спрашивают причину в диалоге.
- [ ] Причина доезжает до гостя на странице статуса заказа.
- [ ] Escape в диалоге отменяет, заказ остаётся нетронутым.

## 8. Долг из прошлых дней

⚠️ Правило исправлено 3 августа (миграция 142). Заявка, **принятая на
кассе**, долгом не считается: её судьба решена в момент приёмки, а
`online_orders` держит статус «accepted» вечно просто потому, что двигать
его больше нечему. Раньше туда попадал весь вчерашний оборот точки.

- [ ] **⛔ Число в `Older unresolved` резко уменьшилось** и совпадает с
      количеством заявок, по которым на кассе так и **не нажали** ни
      «Принять», ни «Отклонить».
- [ ] Внизу — свёрнутая строка `Older unresolved · N`.
- [ ] Подсказка соответствует режиму точки: у точки на кассе — «ждут
      решения на терминале», а не «закройте их из кабинета».
- [ ] Оставшиеся в списке заявки решаются **на кассе**, экран «Онлайн»:
      «Принять» (станет заказом) или «Отклонить» (гость увидит причину).
- [ ] Разворот показывает их по дням: «Yesterday», «1 Aug», «29 Jul».
- [ ] У каждой строки **полная дата**, а не только время.
- [ ] **⛔ Ничего не закрылось и не отменилось само.** Мы принципиально не
      трогаем старые заказы автоматически.

## 9. Поиск и история

- [ ] Найдите старый заказ по номеру — он находится, **не разворачивая
      долг руками** (блок раскроется сам).
- [ ] Поиск по имени гостя и по телефону работает.
- [ ] Вкладка «All orders»: период (сегодня / 7 / 30 дней), листание
      страницами, подпись «51–100 of 145».
- [ ] Смена периода возвращает на первую страницу.
- [ ] Скопируйте адрес с выбранным отбором, откройте в новой вкладке —
      **открывается тот же экран**. Кнопка «Назад» возвращает предыдущий.

## 10. Живая связь

- [ ] Оформите заявку с телефона — в кабинете она появляется **сама**, со
      звуком, без перезагрузки.
- [ ] Индикатор показывает «Live».
- [ ] Выключите Wi-Fi на минуту-полторы: индикатор становится
      «Reconnecting…» или «Data may be stale».
      **⛔ Он не должен оставаться зелёным.**
- [ ] Включите обратно — возвращается «Live», список актуален.

## 11. Телефон и планшет

- [ ] На телефоне это **список**, а не таблица с боковой прокруткой.
- [ ] В каждой строке видно: номер, время, гость, штуки, сумма, состояние.
- [ ] Сумма не обрезана.
- [ ] Фильтры спрятаны за кнопкой «Filters».
- [ ] Заказ открывается листом снизу.
- [ ] Кнопки нажимаются пальцем с первого раза.
- [ ] На планшете — таблица без второстепенных колонок, но с номером,
      временем, гостем, состоянием и суммой.

## 12. Роли

- [ ] Зайдите под сотрудником с ролью **accountant** (или заведите его в
      Team): раздел виден, **⛔ кнопок перехода нет**, вместо них подпись
      «Your role can view orders but not change them».

## Если что-то не сошлось

Напишите, **какой пункт** и что увидели вместо ожидаемого; по возможности
пришлите адрес из строки браузера — в нём записаны раздел, точка, вкладка
и отбор, поэтому экран воспроизводится один в один.

Откат кабинета — обычный откат сборки. Данные при этом не страдают:
миграции `139–141` только добавляют номер, журнал переходов и функцию
чтения; ни одна из них ничего не удаляет и не переписывает.
