## Что было

Главная показывала три счётчика (точки, сотрудники, кассы), список точек,
быстрые действия и карточку продуктов. Это ответ на вопрос «из чего
состоит мой аккаунт». Владелец, открывающий кабинет утром, задаёт другой:
что происходит и что требует внимания.

## Что стало

`backoffice/src/HomeDashboard.jsx` + чистые правила в `dashboard.js`.

### Требует внимания

Первый блок экрана. Каждый пункт обязан вести в конкретный раздел: «что-то
не так» без адреса — это тревога, а не помощь. Порядок — по стоимости
бездействия:

| Пункт | Когда появляется | Куда ведёт |
|---|---|---|
| Касса не выходит на связь | статус `offline` / `error` / `never` | Devices, с советом что делать |
| Заказ ждёт ответа | есть заявки в статусе `new` | Orders |
| Незакрытое с прошлых дней | активные заказы старше начала дня точки | Orders |
| Бронь ждёт подтверждения | визиты в статусе `new` | Reservations |
| Смена не открыта | часть точек без открытой смены | — (открывается на терминале) |
| Канал выключен | онлайн-заказы или бронь выключены в настройках | QR Menu & Online, сразу в нужную вкладку |

Пустой список — нормальный ответ: «Nothing is waiting for you right now»
честнее выдуманного пункта.

Про смену отдельно: когда смена не открыта **нигде**, кабинет молчит —
это ночь, а не проблема. Пункт появляется, только когда одни точки
работают, а другие нет.

### Показатели дня и виджеты

Плитки: выручка за сегодня (`pos_reports`), онлайн-заказы (`orders_desk`),
визиты (`reservations_desk`), состояние смены (`pos_operate`). Панели:
Orders (сколько ждёт, в работе, готово, самое долгое ожидание),
Reservations (ближайшие три визита), Devices (сколько на связи и худший
терминал), Online channels (включены ли заказы и бронь, ссылка «Open as
guest»).

Ни одного придуманного показателя — всё читается с сервера:

| Виджет | Источник |
|---|---|
| Выручка | `sales_report` за сегодня в зоне точки |
| Смена | прямой select `shifts` под RLS организации (политика 008) |
| Заказы | `online_orders`, активные |
| Визиты | `reservations` от начала дня |
| Кассы | `get_backoffice_fleet` (телеметрия 074/097) |
| Каналы | настройки точки |

**Чего в дашборде нет и почему.** План просит показывать
«неопубликованные изменения каталога». В базе нет ни черновиков, ни
статуса публикации — обещать это нельзя. Появится тогда же, когда
появится модель черновика (Phase 5 плана и отложенный пункт 5b старого).

### Частичный отказ — состояние продукта

Загрузка идёт `Promise.allSettled`. Если упал отчёт по продажам, владелец
всё равно видит заказы, брони и молчащие кассы: упавший показатель
показывает «—», а в шапке появляется «Some data could not be loaded».
Проверено тестом с управляемым отказом источника.

## Попутно закрыт дефект Phase 0

Строка журнала на 390px вылезала за панель на 9px и давала
горизонтальную прокрутку **всей странице** (Phase 0, п. 1). Причина не в
отступах: элемент grid по умолчанию имеет `min-width: auto`, то есть не
может стать уже своего `max-content`. Лечится одной строкой
(`.activity-list > *, .data-list > * { min-width: 0 }`), закреплено
браузерным тестом на нарочно длинных подписях.

Теперь во всех 40 кадрах стенда горизонтальное переполнение равно нулю.

Отдельно: браузерные наборы теперь умеют подменять Supabase — без этого
виджеты дашборда нечем проверить, они существуют только в загруженном
состоянии, а серверный рендер эффекты не выполняет.

Нестабильность, замеченная один раз: набор дашборда упал по таймауту
`waitForSelector`, когда одновременно с тестами шла съёмка стенда (два
Chrome на одной машине). Три последующих прогона подряд — зелёные.

## Что осталось

- **«Что дальше» словами.** План просит подсказывать следующий шаг. Сейчас
  подсказка выводится только из проблем; сценарий «всё хорошо, займитесь
  вот этим» требует продуктового решения, а не кода.
- **Дашборд не помнит выбранную точку в адресе** (у него нет переключателя
  в шапке): сводка считается по точке из общего контекста кабинета.
- **Черновики каталога и статус публикации** — нет модели в БД.
