# Back office platform — Phase 1: токены и общие компоненты

Дата: 2026-08-02. План: `docs/claude-angle-platform-backoffice-master-plan.md`,
раздел «Phase 1: design tokens and shared components». Базовая линия:
`docs/backoffice-platform-phase0.md`.

Не задеплоено, не закоммичено. Изменения лежат в рабочем дереве.

## Задача

Кабинет собран из литералов. Кнопка — это класс, который автор экрана
вспомнил; цвет — hex, который он подобрал; вкладки — `role="tablist"`,
который ничего не умеет. Пока это так, любая следующая фаза (шелл,
дашборд, каталог) будет чинить одно и то же место в тринадцати экранах
по-разному.

Цифры на входе (Phase 0): 606 литералов цвета на 164 значения при двух
CSS-переменных на весь файл; 151 упоминание четырёх кнопочных классов;
восемь `role="tablist"`, ни один не работает с клавиатуры; ровно одно
правило `:focus-visible` на весь кабинет.

## Что сделано

### 1. Слой токенов

36 переменных в `:root`: поверхности, шесть ступеней текста, четыре
границы, чернила, опасность и успех, две тени и кольцо фокуса, сетка
отступов 4/8/12/16/24/32, радиусы, высоты контролов (32/40/44).

Имена смысловые (`--c-text-muted`), а не по внешнему виду (`--grey-500`):
экран просит роль, а не оттенок, иначе смена палитры снова превращается в
замену по файлу.

Введение шло двумя отдельно проверяемыми шагами:

| Шаг | Что делает | Визуальный эффект |
|---|---|---|
| Именование | 407 литералов заменены на `var(--…)` с тем же значением | **нулевой**: 37 из 40 кадров совпали побайтово, три остальных нестабильны сами по себе (см. ниже) |
| Сведение | 46 значений-близнецов (111 вхождений) сведены к шкале | максимальная разница канала **6 из 255**, порог отбора ΔE ≤ 2,5 |

Сводились только серые: насыщенные цвета к шкале не приводились, потому
что «красный ошибки» и «красный кнопки» — это продуктовое решение, а не
округление оттенка.

Итог: 531 использование токенов, 167 литералов на 99 значений осталось.
Из них 39 значений (56 вхождений) — насыщенные: палитра статусов, её
надо решать отдельно и осознанно.

### 2. Общие примитивы

`backoffice/src/ui/`:

| Компонент | Что перестаёт зависеть от внимательности автора |
|---|---|
| `Button` | `type="button"` по умолчанию — кнопка внутри формы больше не отправляет её случайно; `busy` даёт `disabled` + `aria-busy`; неизвестный вариант не роняет экран |
| `IconButton` | `label` обязателен: кнопка-иконка не может остаться безымянной |
| `Tabs` | roving tabindex, стрелки, Home/End, прокрутка активной вкладки в видимую область, разворот стрелок в RTL |
| `PageHeader` | компактный заголовок раздела — режим по умолчанию |
| `Panel` | шапка рисуется только когда есть что писать |
| `SearchField` | подпись есть всегда и не исчезает вместе с плейсхолдером |
| `StatusBadge` | состояние всегда словом; точка помечена `aria-hidden` |
| `EmptyState`, `EmptyPanel`, `ErrorText` | пустое и ошибочное состояние — часть продукта, а не забытая ветка |

Классы намеренно оставлены прежние: фаза вводит реализацию, а не новый
внешний вид. Поэтому её результат и можно проверять попиксельно.

### 3. Видимый фокус

Правило `:focus-visible` для кнопок, ссылок, вкладок и полей — через
`:where()`, то есть с нулевой специфичностью: где экран задал фокус сам,
всё остаётся как было. Мышиный фокус не подсвечивается.

До этого в кабинете было одно такое правило (на пресете фона), а местами
обводка ещё и гасилась.

### 4. Миграция показательного раздела

`DevicesManager` переведён на примитивы целиком: заголовок, поиск,
кнопки, панели групп, метка состояния, оба пустых состояния, ошибка.

Вкладки каталога (`MenuManager`) переведены на `Tabs` — это самый
растиражированный сломанный паттерн, и его почина ждали все восемь
объявлений `tablist`.

| Что | Результат |
|---|---|
| `npm test` | **190 тестов, 0 падений** (было 167): +14 рендер-тестов примитивов, +6 на строку устройства, +3 браузерных на клавиатуру и фокус |
| `npm run build` | ок: `index-BSxQbnMH.js` 727,68 kB (gzip 204,99), `index-CL7sTRat.css` 79,05 kB (gzip 14,66) |
| Кадры стенда | 40 в трёх вьюпортах, `screenshots/backoffice/platform-phase1-*.png` |

Пиксельная сверка (стенд с замороженными часами, иначе сравнение ловит
время вместо стилей):

- **именование токенов** — 37 из 40 кадров идентичны побайтово; кадры
  Devices нестабильны между любыми двумя прогонами из-за «Updated HH:MM»,
  поэтому часы в стенде теперь фиксируются;
- **миграция компонентов** — 37 из 40 кадров идентичны побайтово; в трёх
  кадрах Devices изменились 120 пикселей из 1,3 млн (0,009 %), максимум
  канала 34: это сглаживание строки «2 devices», которая раньше состояла
  из трёх текстовых узлов, а теперь из одного;
- **сведение оттенков** — меняется 1–5 % пикселей, максимум канала **6 из
  255** на всех проверенных кадрах; при увеличении в 3 раза разница не
  видна.

Клавиатура проверена в настоящем браузере: Tab заводит в группу вкладок
один раз, стрелки ходят по кругу, Home/End прыгают по краям, следующий Tab
уводит из группы; в `dir="rtl"` стрелка вправо ведёт к предыдущей вкладке.
Отдельная проверка: клавиатурный фокус виден, мышиный — нет.

## Риски

1. **Сведение оттенков необратимо на глаз, но не на числа.** Список из 46
   слияний и порог ΔE ≤ 2,5 зафиксированы здесь; если владелец увидит
   разницу на настоящем экране, откатывается один шаг, а не вся фаза.
2. **Стенд — не прод.** Пиксельная сверка сделана на фикстурах в headless
   Chrome. Шрифтовое сглаживание на macOS и на реальном мониторе владельца
   отличается, поэтому «0 отличий» здесь означает «мы ничего не сдвинули»,
   а не «на любом устройстве выглядит так же».
3. **Изменился `backoffice/test/register.mjs`** — тестовый загрузчик
   теперь видит подкаталоги `src/`. Без этого `src/ui/*` не читались бы
   как JSX.
4. **`package.json`**: в `npm test` добавлен путь `backoffice/src/ui/*.test.js`.
   Новый подкаталог с тестами придётся добавлять так же, пока не перейдём
   на обход каталога.
